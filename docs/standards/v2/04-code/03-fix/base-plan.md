# Базовый план: 04-code-fix

## 0. Воспроизведение бага (Red run)

Фикс начинается с фэйлящего теста который воспроизводит баг.

1. Напиши тест (или убедись что существующий тест воспроизводит проблему)
2. Запусти — тест должен упасть: `verify: тест падает без фикса (Red run)`
3. Только после этого — пиши фикс
4. Запусти тесты — тест должен пройти: `verify: тест проходит после фикса (Green run)`

Это не опционально: если тест не падает до фикса — либо тест не воспроизводит проблему, либо проблемы нет.

## 1. Сбор контекста

- Прочитай `04-code/02-review/report-*.md` — список замечаний с классификацией
- Прочитай затронутые файлы кода

## 2. Согласование плана

- Покажи план фикса пользователю: что именно меняется и почему
- Дождись подтверждения

## 3. Исправление

Исправляй только то что указано в review. Не рефакторь то что не затронуто замечаниями.

Приоритет: сначала `critical`, потом `warning`, потом `note`.

После каждого исправления — держи тесты зелёными. Если фикс ломает тест — это сигнал что фикс неверен или тест неполный.

Держи каждый модуль ≤ 150 строк. Если фикс требует разбиения модуля — разбей.

## 4. Невозможные фиксы

Если замечание нельзя исправить без изменения acceptance или spec:
- Запиши `clarification` в report
- Объясни: что конкретно в acceptance/spec мешает
- Откат через оркестратора к `02-acceptance/03-fix`

## 5. Проверка после фикса

Запусти тесты. Ожидаемый результат: все зелёные (как были до фикса).

## 6. Grep-конвенция

Перед закрытием замечания — если ревью указало на паттерн (не буквальную строку, а класс проблем):
- сформулируй паттерн словами
- сделай grep по файлу/пакету
- убедись что других экземпляров нет

## 7. Формирование отчёта

В frontmatter `report-NNN.md` обязательно укажи:

```yaml
in-response-to: tasks/<feature>/stages/04-code/02-review/report-NNN.md
```

Содержимое отчёта:
- Список исправленных замечаний (ссылка → что сделано)
- Список неисправленных с объяснением

## Скрипты

```bash
# Начало: написать brief-NNN.md, затем
python3 scripts/set-step-status.py <feature> <stage/step> in-progress --comment "..."
# Конец: написать report-NNN.md, затем
python3 scripts/set-step-status.py <feature> <stage/step> done --comment "..."
```

## Финальный шаг: notes/complaints

```bash
python3 scripts/log-note.py --agent <агент> --message "[propose] текст"
python3 scripts/log-complaint.py --agent <агент> --message "текст"
```

Теги: `[doc]`, `[propose]`, `[friction]`, `[miss]`, `[rework]`, `[whatever]`
Минимум — одна строка.

## Движение вперёд и назад

**Done когда:** все исправимые замечания закрыты, тесты зелёные, report написан
**Следующий:** 04-code/02-review (повторное ревью)
**Передаём:** report-NNN.md

**Возврат назад:**
- Замечание требует изменения acceptance → `clarification`, откат к 02-acceptance/03-fix
