# Базовый план: 06-retro-recall

## 0. Gate: проверка готовности pipeline

Перед recall убедись что все предыдущие этапы завершены. Скрипт проверяет это автоматически:

```bash
python3 scripts/set-step-status.py <feature> 06-retro/01-recall in-progress
```

Если `gate-done-steps` содержит незакрытые шаги — скрипт откажет и покажет их список. Варианты:
1. **Завершить шаги** — вернуться, закрыть, затем запустить recall
2. **Явное решение пропустить** — добавить запись в `status-log.md` с обоснованием, затем снять gate вручную

Gate-шаги (финальные шаги каждого этапа):
- `00-research/02-web`
- `01-spec/02-review`
- `02-acceptance/02-review`
- `03-tests/04-run`
- `04-code/04-testing`
- `05-docs/02-review`

## 1. Prime Directive и review предыдущего ретро

**Prime Directive** (Norm Kerth): каждый агент действовал из лучших побуждений при имеющихся данных, инструментах и возможностях. Критика направлена на систему и процесс — не на конкретного агента.

**Review предыдущего RETRO.md**: если в директории фичи (или смежных фич) есть предыдущий `RETRO.md` с action items — прочитай его. Для каждого item: выполнен / не выполнен / устарел. Устаревшие — явно списать, не тащить вперёд.

## 2. Агрегация notes/complaints

До параллельного recall — собери все notes/complaints написанные по ходу работы над фичей:

```bash
find tasks/<feature>/stages/ \
  \( -name "notes-*.md" -o -name "complaints-*.md" \) \
  | grep -v "06-retro/01-recall"
```

Для каждого найденного файла:
- Определи участника по имени файла (`notes-ада.md` → **Ада**)
- **Дополни** (append) соответствующий файл в `stages/06-retro/01-recall/` с разделителем источника:
  ```
  <!-- source: stages/<этап>/<шаг>/notes-<агент>.md -->
  ```
- Если файла ещё нет в recall — создай его

Файлы пользователя (`notes-user.md`, `complaints-user.md`) агрегируются так же.

## 3. Определение участников

Определи кто участвовал по наличию notes/complaints после агрегации, а также по директориям stages/:

- Есть `01-spec/`, `02-acceptance/` с артефактами → **Танк**
- Есть `04-code/` с артефактами → **Ада**
- Есть `*/02-review/` с артефактами → **Гримм**
- Есть `03-tests/` с артефактами → **Кроули** и **Азирафаль**
- **Харли** — всегда, как оркестратор

## 4. Параллельный recall

Спауни всех участников одновременно с `mode: bypassPermissions`.

Каждый агент:
1. Читает агрегированные `notes-<агент>.md` и `complaints-<агент>.md` из `stages/06-retro/01-recall/`
2. Читает свои артефакты фичи (reports, briefs) для контекста
3. **Дополняет** свои файлы в `stages/06-retro/01-recall/` новыми наблюдениями — не перезаписывает

### Формат `notes-<агент>.md`

Одна строка = одно наблюдение с тегом:

```
[rework] что пришлось переделывать и почему
[friction] что замедляло работу
[miss] что забыли или пропустили
[propose] предложение по улучшению процесса или инструментов
[doc] нюанс который стоит задокументировать
[whatever] не вписывается — разберёмся на ретро
```

### Формат `complaints-<агент>.md`

Сырые жалобы без тегов и без фильтра. Что раздражало, что казалось бессмысленным, на кого злился.

## 5. Формирование отчёта

После завершения всех агентов:
- Сводка: какие файлы обновлены, сколько наблюдений добавил каждый
- Незаполненные файлы если агент ничего не нашёл
