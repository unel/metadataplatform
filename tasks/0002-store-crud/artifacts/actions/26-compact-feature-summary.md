# Action: управление контекстом при восстановлении сессии

## Проблема

Контекст жрётся по кругу: при каждом восстановлении сессии оркестратор заново читает
одни и те же файлы — все status-log, все report'ы, спеку, acceptance.
Часть состояния живёт только в памяти агента и теряется при прерывании.

Узкое решение (STATUS.md как компактный срез) — это один из подходов,
но не решает задачу в полноте: откуда агент знает что читать первым?
сколько контекста уходит на "понять где мы"? как не перечитывать то что не изменилось?

## Пространство решений (нужно продумать)

- Иерархическое сжатие: STRUCTURE.md задачи → STATUS по шагам → детали по запросу
- Скрипт `feature-status.sh` как единая точка входа для восстановления статуса
- Формат report-NNN.md с явным разделом "контекст для восстановления"
- Memory-файлы оркестратора: что сохранять между сессиями, что выбрасывать
- Хук на завершение сессии: автосохранение состояния в компактную форму

## Не решение

`STATUS.md` поддерживаемый вручную — будет расходиться с реальностью.
Генерация STATUS.md скриптом — частичное решение, не закрывает всю проблему.
