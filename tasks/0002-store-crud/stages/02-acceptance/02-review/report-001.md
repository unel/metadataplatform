### AR-1 [пробел в acceptance]

**Сценарий**: отсутствует
**Spec**: §5.1, НФТ-О-1

Spec §5.1 явно задаёт: при parse error (json.Decoder вернул синтаксическую ошибку) логировать как
`ERROR op=unknown parse_error="<text>"`. AC-ROUTER-09 проверяет только то что соединение
закрывается. Поведение логирования при parse error не покрыто ни одним сценарием.

Нужен сценарий: роутер получает невалидный JSON → в лог записана строка уровня ERROR содержащая
поле `parse_error` с текстом ошибки.

### AR-2 [пробел в acceptance]

**Сценарий**: отсутствует
**Spec**: НФТ-О-2

Spec НФТ-О-2 задаёт два конкретных лог-события для конструктора FS-стора:
- Успех: `INFO store/fs initialized basedir=<path>`
- Ошибка: `ERROR store/fs init failed basedir=<path> error=<...>`

Ни AC-FS-INIT-01, ни AC-FS-INIT-02 не проверяют логирование инициализации. AC-FS-INIT-01
проверяет только возврат (*Store, nil) и наличие директорий. AC-FS-INIT-02 проверяет только
возврат (nil, err).

Нужны два сценария: успешная инициализация → INFO в лог с basedir; ошибка инициализации →
ERROR в лог с basedir и error.

### AR-3 [проблема качества]

**Сценарий**: AC-NFT-ATOMIC-02
**Spec**: §6

Then: "uuid.New() (UUID v4) в кодовой базе не использован"

Then описывает статическую проверку кодовой базы, не наблюдаемое поведение системы. Ни один
тест не может проверить "в кодовой базе не используется функция X" через вызов системы.
Это code review пункт, не acceptance-сценарий.

Переписать как поведенческий: клиент вызывает uuid.NewV7(), передаёт результат как id в Upsert
→ операция успешна. Либо убрать в code review checklist.

### AR-4 [проблема качества]

**Сценарий**: AC-ENTITY-UPSERT-01
**Spec**: §3.1 п.5

Spec §3.1 п.5: "Значения created_at и updated_at из входящего запроса игнорируются."

Then утверждает "входящие значения игнорированы", но Given не задаёт конкретные входящие
timestamps. Без конкретного значения в Given проверить игнорирование невозможно — это
декларация намерения, а не верифицируемый тест.

Given должен содержать Entity с явным CreatedAt/UpdatedAt (например time.Date(2000,1,1,...)).
Then должен проверять что в сохранённом файле эти поля не равны заданному значению.
