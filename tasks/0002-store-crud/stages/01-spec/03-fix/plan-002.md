# План исправлений: run 2

## CR-9 [warning] — Failure mode инициализации FS

**Проблема:** §4.1 говорит что субдиректории создаются при инициализации, но что происходит при ошибке — не определено. Роутер стартует без рабочего хранилища, все upsert падают с WRITE_ERROR без понятной причины.

**Изменение:**
- §4.1 — добавить: "Если `os.MkdirAll` возвращает ошибку — конструктор возвращает ошибку. Инициализация прерывается."
- §НФТ-О-2 — добавить строку для ошибки: `ERROR store/fs init failed basedir=<path> error=<...>`
- Таблица failure modes уровня инициализации — добавить отдельным блоком (не в операционные таблицы).

## CR-11 [note] — Формат лог-строки для list

**Проблема:** §НФТ-О-1 определяет формат `DEBUG op=<op> type=<type> id=<id>` — но `list` не принимает `id`, поле неприменимо.

**Изменение:**
- §НФТ-О-1 — добавить специальный формат для list: `DEBUG op=list type=<type> count=<N>`
- Явно: для операций get/delete/upsert — `id=<id>`, для list — `count=<N>`, поле `id` опускается.

## CR-12 [note] — Конфликт id в envelope и data при upsert

**Проблема:** §5.2 описывает envelope с полем `id`, §3.1 говорит что id берётся из data.id — но явно это не сказано. Поведение при `{"op":"upsert","id":"aaa","data":{"id":"bbb"}}` не определено.

**Изменение:**
- §5.2 — добавить одну строку после описания маппинга: "для `upsert` поле `id` в envelope игнорируется — `id` берётся из `data`".

## CR-13 [note] — created_at/updated_at не включены в алгоритм §4.3

**Проблема:** §4.3 описывает IO-алгоритм (CreateTemp → encode → Sync → Close → Rename), но логика временны́х меток из §3.1 туда не дублируется. Code-writer читающий §4.3 изолированно пропустит выставление меток.

**Изменение:**
- §4.3 — добавить явный шаг перед encode: "1a. Выставить `created_at`/`updated_at` по правилам §3.1: при создании — `created_at = time.Now().UTC()`; при обновлении — `created_at` из существующей записи. `updated_at = time.Now().UTC()` всегда. Значения из входящего запроса игнорируются."
- Ссылка на §3.1 не заменяет явный шаг, но может быть добавлена дополнительно.
