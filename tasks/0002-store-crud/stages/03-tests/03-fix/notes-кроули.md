# Notes: store/crud adversarial tests

[doc] AC-NFT-ATOMIC-01 использует subprocess-паттерн (TEST_ATOMIC_HELPER=1 env var).
Это стандартный Go-подход для тестирования SIGKILL. Но требует что test binary
компилируется до запуска — `go test -c` сначала, потом `./binary -test.run=...`.
При обычном `go test` работает через `os.Args[0]` который и есть test binary.

[propose] router.New() в тестах принимает logger как аргумент — это правильно.
Но если реализация не принимает logger в конструкторе, а использует slog.Default() —
все тесты на логирование упадут. Надо убедиться что спека явно требует инъекцию logger.
В spec v1.4.0 это не формализовано явно. Флаг для code review.

[friction] Нет go.mod в store/tests/ — тесты будут компилироваться
как часть модуля github.com/unel/metadataplatform. Это нормально пока
store/fs и store/router пакеты существуют. Сейчас их нет — тесты не скомпилируются.
Это ожидаемое поведение (red phase TDD).

[miss] AC-ENTITY-DELETE-04 в acceptance говорит "через mock FS или временное ограничение прав".
Реализовал через chmod директории. Mock-вариант был бы чище но требует интерфейс FS
которого в спеке нет. Chmod — реальная FS, это adversarial тест — честнее.

[doc] os.Chmod симуляция прав — не работает под root. Если тесты запускаются
в docker-контейнере от root — chmod-тесты будут ложноположительными (пройдут
даже при неправильной реализации). Надо добавить skip: if os.Getuid() == 0.
Записано как техдолг.
