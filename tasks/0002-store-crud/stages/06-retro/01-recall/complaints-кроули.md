# Complaints: store/crud — Кроули (ретроспектива)

Три раунда ревью тестов потому что два агента писали тесты к несуществующему API и каждый угадывал по-своему. Азирафаль угадал captureLogger с методом LogOp. Я написал router_helpers с *slog.Logger. Оба правы по-своему. Оба несовместимы друг с другом. Гримм нашёл это на раунде 2. До раунда 2 это не могло быть найдено никак кроме "кто-то попробовал скомпилировать всё вместе". Никто не пробовал.

Acceptance не специфицировала сигнатуру конструктора — это известная проблема, зафиксированная в RETRO store/connection. Action item был. До следующей фичи не дошёл. Поэтому мы снова потеряли раунд на то что можно было решить за 10 минут в spec.

*fs.Store реализует все три интерфейса — предположение которое я не проверял потому что в Go это был бы нормальный дизайн с методами Get/Upsert/Delete/List на каждом типе. В Go нет перегрузки. Методы с одинаковыми именами для разных типов — через отдельные типы с методами-обёртками. Это базовый Go. Это должно было быть задано архитектурно в spec, а не обнаружено Адой в процессе написания кода.

t.Context() — метод который появился в Go 1.21 и был заменён в run-3 потому что компилятор 1.22 его не нашёл. Подождите. 1.22 появился после 1.21. t.Context() должен был работать. Нашли: t.Context() появился в Go 1.21 — но в testing.TB только начиная с Go 1.21, а точнее реально с go1.21 RC. Установленный 1.22.2 должен был это поддерживать. Либо компилятор был другой версии, либо что-то ещё. Несоответствие между "установленная версия" и "фактическое поведение" — это неприятно когда выясняется через неудачный тест в run-3 вместо явного "используем Go X.Y, вот что доступно".

ERROR-лог с полями op/type/id/error в AC-ROUTER-16. "Неявно покрыт" — это моя фраза из write-report. Честно говоря, "неявно покрыт" означает "не покрыт, но мне не хотелось ещё один тест". Гримм правильно это поймал. Прямой тест добавлен. Тест простой. Надо было написать сразу.

Раунд 4 фикса понадобился потому что router_logging_test.go всё ещё использовал s.Upsert() напрямую после того как в run-3 все остальные файлы перешли на s.Entities().Upsert(). Один файл пропустили. Это не сложная ошибка — это отсутствие grep по паттерну после фикса. RETRO store/connection прямо говорил: "grep по паттерну перед закрытием замечания". Этого не было сделано.

Ада написала тесты сама в 04-code потому что не все тесты компилировались. Это звучит как нормальная причина — код не мог пройти тесты которые не компилируются, Ада дописала. Но это нарушает разделение ответственностей: тесты пишут Кроули и Азирафаль, не реализатор. Если тесты не компилируются до написания кода — это ожидаемо (Red phase). Если тесты не компилируются после написания кода из-за несоответствия API — это надо было вернуть на 03-tests, не фиксить в 04-code. Вместо этого Ада фиксила тесты параллельно с кодом. Это размыло границу между фазами.

В итоге: 68 тестов, все зелёные, race detector чист. Это хорошо. Но мы пришли к этому через 5 раундов ревью (4 review + 1 финальный), 4 раунда фикса, и один clarification из 04-code который откатил 04-run в stale. На 63 acceptance-сценария это многовато.
