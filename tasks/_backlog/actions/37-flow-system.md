# Action: система флоу как таковая

## Проблема

Workflow v2 подразумевает конкретный набор этапов и шагов (spec → acceptance → tests → code → docs → retro), но понятия "флоу" как конфигурируемой сущности нет. Нет механизма определить другой набор шагов, нет формата описания флоу, нет процесса инициализации скелета на его основе.

Это блокирует: задачи не по фиче, упрощённые флоу, потенциальные кастомные флоу.

## Решение (нужно продумать)

- Формат описания флоу: какие этапы и шаги, в каком порядке
- Как скелет фичи (stages/) инициализируется на основе выбранного флоу
- При инициализации скелета — прописывать в frontmatter каждого `status-log.md` поля `next-success-step` / `next-fail-step` / `previous-step` (и `next-stage` / `previous-stage` на уровне этапов) — чтобы граф зависимостей был явным и машиночитаемым
- Scaffold-скрипт (`scripts/scaffold-feature.py` или аналог): создаёт дерево `stages/` с `status-log.md` (включая frontmatter) на основе выбранного флоу; без него `begin-step.py` / `end-step.py` / `cascade-stale.py` не работают
- Где живут определения флоу (docs/standards/v2/flows/? или inline в скриптах?)
- Как менять флоу у уже начатой фичи
