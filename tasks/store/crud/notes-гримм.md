# notes-гримм: store/crud

[rework] spec потребовала 5 ревью-итераций и 21 замечание. CR-14—CR-20 появились потому что каждый фикс генерировал новые несоответствия: fix одного требования создавал противоречие с другим. Спека писалась инкрементально, не как цельный документ — каждая итерация чинила предыдущую брешь без взгляда на целое.

[rework] CR-14 (named return) — фундаментальная ошибка спеки: предписала паттерн `defer func() { if err != nil {...} }()` без указания что функция должна иметь named return. Паттерн физически не работает без этого. Code-writer выполнил бы букву спеки и получил нерабочий cleanup.

[rework] CR-20 (json.Decoder recovery) — спека создала физически несовместимое требование: decoder продолжает работу после ошибки decode, но `json.Decoder` в таком состоянии недетерминирован. Обнаружили только на 4-м раунде.

[friction] Без shell tool поиск файлов в untracked директории — лотерея. Потратил N попыток на угадывание имён файлов в `processes/*/02-review/`. Реальный паттерн `report-001.md` нашёл только через MEMORIES.

[friction] report-003 для тестов имеет статус `done`, но в MEMORIES написано `done (run 5)`. Значит были дополнительные итерации после того как тесты уже были пройдены — скорее всего из-за смены кода. Каскадный сброс не отражён в статусе report-003.

Спека добавила `filepath.Join(dir, id+".json")` и запрет прямой конкатенации, но не добавила требование проверки что результат остаётся внутри basedir после нормализации. [miss] Тест `TestEntity_Upsert_WriteError_NoTempFileLeft` тихо пропускает все assert'ы при chmod-fail — нашёл в run-2. Паттерн молчащего пропуска проверки без `t.Skip` — тест всегда зелёный, ничего не проверяет. Это то же что `waitForMsg` из store/connection.

[propose] CR-14 вскрыл системную проблему: спека предписывает конкретные Go-паттерны (named return, defer, filepath.Join) но не имеет раздела "Предусловия реализации" где бы явно перечислялись требования к сигнатурам. Нужен стандарт: если спека диктует паттерн — она обязана перечислить все синтаксические предусловия этого паттерна.

[propose] acceptance-review должна содержать пункт: "каждый сценарий воспроизводим в тесте — описан конкретный механизм". AR-3 поймал статическую проверку кодовой базы замаскированную под acceptance-сценарий. Это происходит когда пишущий не думает о тестировании.

[propose] spec-review должна включать пункт проверки совместимости предписанных паттернов с языком. "Предписанный паттерн физически работает с предписанной сигнатурой" — CR-14 и CR-20 оба были о физической невозможности.

[doc] json.Decoder после decode-ошибки: состояние недетерминировано, следующий Decode() может не восстановиться. Это Go-специфика которую нужно документировать в стандартах — любая фича с JSONL-роутером наткнётся на то же.

[doc] `t.Skip` при root/chmod-непримениомсти — конвенция для тестов которые зависят от файловых прав. Если запускаем под root — chmod игнорируется, тест бессмысленен. Без Skip — тест зелёный, вводит в заблуждение. Нужно в TDD-стандарт.
