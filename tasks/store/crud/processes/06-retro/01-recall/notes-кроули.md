# Notes: store/crud — Кроули (ретроспектива)

[friction] Три раунда ревью тестов из-за одного фундаментального пропуска: Азирафаль и я не согласовали сигнатуры API до написания. Два агента написали две несовместимые версии router.New и r.Handle. Это не баг тестов — это отсутствующий шаг "согласование интерфейсов" до test-write.

[miss] Предположение что *fs.Store реализует все три интерфейса (Entity + Relation + Job) напрямую — неверное для Go. В Go нет перегрузки методов. Это архитектурное предположение которое должно было быть зафиксировано в spec или acceptance явно, а не угадано на этапе test-write. Обнаружено только когда Ада написала реализацию.

[rework] captureLogger → slog.Logger: кастомный тип логгера в happy-тестах пришлось выбросить на втором раунде фикса. Это прямое следствие того что spec не специфицировал интерфейс логгера. Action item из RETRO store/connection ("шаблон спеки: обязательный пример лог-строки") — не был исполнен до этой фичи.

[friction] t.Context() в nft_test.go — применён метод из Go 1.21 при компиляторе 1.22.2. Не упало, но run-3 потребовал фикса через Аду. Если бы тест запускался раньше — нашли бы сразу. Ценность раннего red-run: не просто "тест падает" а "тест компилируется".

[propose] Шаг 04-run/01 должен запускать `go build ./...` по тестовым пакетам отдельно от `go test`. Compile error — это другая категория провала чем test failure. Сейчас они неразличимы в статус-логе: оба пишутся как "setup failed".

[miss] AC-ROUTER-16 — покрыт только "неявно" в первой версии. Прямой тест на ERROR-лог с полями op/type/id/error не был написан до ревью. Это не случайность: я не нашёл в AC явного требования к полям. Если acceptance пишет "роутер логирует ошибку" — это не specification, это описание намерения.

[doc] os.Chmod-тесты (chmod 000) не работают от root. Добавлен t.Skip(). Но: нет автоматической проверки что skip-тесты не накапливаются без ревью. Тест который скипается — это потенциально мёртвый тест. Нужен чек-пункт в test-review: "есть ли t.Skip — почему, при каких условиях воспроизводим".

[doc] Subprocess-паттерн в atomic_test.go (TEST_ATOMIC_HELPER env var + os.Args[0]) — правильный Go-идиом для SIGKILL-тестов, но требует что test binary уже скомпилирован. При `go test -count=1` бинарь пересобирается и os.Args[0] указывает на свежий. Это нормально. Но если тест запускается через IDE которая кеширует — потенциально вызывает старый бинарь. Зафиксировано как известное ограничение.

[propose] Маркер готовности в atomic_test.go (файл .ready) — правильнее чем time.Sleep(30ms), но теперь у нас временный файл в basedir который нужно очищать. t.TempDir() очищает всё — это нормально. Но паттерн "файл как IPC между parent и subprocess" стоит задокументировать в стандартах TDD как рекомендованный подход для process-level тестов.

[whatever] Action items из RETRO store/connection: из 8 пунктов "берём в работу" — ни один не был выполнен до старта этой фичи. Это не упрёк — просто наблюдение: ретро накапливает хорошие идеи которые остаются в RETRO.md и не конвертируются в задачи. Нужен механизм "ретро → backlog".

[friction] Стейт-лог в 04-run содержит запись "stale" из-за clarification от Ады (перегрузка методов в Go невозможна). Это означает что тесты на шаге 03-tests дошли до done, потом вернулись к фиксу из-за проблемы которую мог бы поймать компилятор раньше. Red-run-1 должен был дать compile error с конкретной причиной — дал setup failed с "store не существует". Нет механизма отделить "код не написан" от "тест неправильно написан".
