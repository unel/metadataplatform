# Action: разделы "Контракт" и "Реализация на Go" в шаблоне spec

## Проблема

Спека store/crud смешивала требования с имплементационными решениями: `filepath.Join`, `named return`, конкретные сигнатуры — всё в одном тексте. CR-15 предписал `filepath.Join` без проверки traversal — тот же баг всплыл как CRITICAL-1 в code-review. 5 итераций / 21 замечание — значительная часть из них была к стилю и Go-специфике, а не к требованиям.

## Решение

В шаблоне spec явно разделить:

```markdown
## Контракт (стек-независимо)
Что система делает, семантика операций, гарантии, failure modes.
Пример: "Create сохраняет entity и возвращает ошибку если ID уже существует"

## Реализация на Go
Конкретные паттерны, типы, сигнатуры, пакеты.
Пример: "Использовать filepath.Join для построения пути. Валидация ID — отдельная функция validateID."
```

Ревью spec проверяет "Контракт" на корректность требований, "Реализация" — на соответствие стандартам Go.
