- Три сущности: `entity`, `relation`, `job`
- Операции: `upsert`, `delete`, `get` (по id)
- JSONL-протокол уже работает (store/connection done)
- Нужны Go-интерфейсы: `EntityStore`, `RelationStore`, `JobStore`
- Нужна FS-реализация (JSON-файл на диск, для отладки)
- Не входит: PostgreSQL-реализация, Query DSL, cursor pagination, FOR UPDATE SKIP LOCKED
- Зависимость: store/connection — done

## Пробелы — нужно выяснить

### 1. Сигнатуры интерфейсов

README.md говорит "расписать точные сигнатуры" — но не указывает их. Нужно выяснить:
- `upsert` — создаёт или обновляет? Что является ключом при update (только `id`)?
- `get` — возвращает одну запись или ошибку, если не найдена? Какой тип ошибки?
- `delete` — идемпотентный? (удаление несуществующего = ошибка или ok?)
- Нужен ли `list`/`getAll` без фильтрации — или только `get` по id?

### 2. Формат FS-реализации

README.md говорит "конкретный формат — на усмотрение Танка", но пользователь написал это. Нужно проверить:
- Один файл на тип (entities.json, relations.json, jobs.json) vs один файл на запись (entities/uuid.json)?
- Есть ли предпочтение по человекочитаемости vs простоте кода?

### 3. Атомарность записи и конкурентный доступ

README.md явно просит это расписать. Нужно выяснить:
- FS-реализация только для отладки/разработки — значит строгой атомарности не требуется? Или всё же нужна?
- Конкурентный доступ: один процесс или несколько клиентов пишут одновременно?
- Что важнее: простота реализации или корректность при параллельных операциях?

### 4. Маппинг op → метод

- `op: upsert` → `EntityStore.Upsert(...)` — это явно
- Как обрабатывать неизвестный op? Ошибка на уровне роутера?
- `op: delete` без `id` — какое поведение?

### 5. Генерация ID

- ID генерирует стор или клиент передаёт? Если upsert без id — создаём новый?
- PROJECT.md говорит UUID v7 — это фиксированное требование или только для Postgres-реализации?

### 6. Поля `created_at` / `updated_at`

- FS-реализация выставляет timestamps или они приходят в data?
- `updated_at` при upsert — всегда перебиваем текущим временем или только если запись меняется?

## Порядок вопросов

1. Интерфейсы (upsert-семантика, get-семантика, delete-идемпотентность, нужен ли list?)
2. FS-формат (один файл на тип vs файл на запись)
3. ID и timestamps (кто генерирует, uuid v7 обязателен?)
4. Атомарность и конкурентность (насколько строго для FS?)
5. Граничные случаи роутера (неизвестный op, отсутствующий id)
