Acceptance описывает поведение системы хорошо — 45 сценариев, каждый с четким Given/When/Then. Это приятно. Но есть несколько мест где пришлось угадывать:

1. Сигнатура логгера для fs.New и router.New нигде не задана. Acceptance говорит что "логгер подключён к конструктору" — это достаточно для тестирования поведения, но не для определения API. Я принял решение самостоятельно. Если код-реализатор примет другое — тесты придётся переписать, и это будет честно, но немного обидно.

2. Метод Handle роутера — acceptance описывает что роутер обрабатывает net.Conn, но не называет метод. Назвал Handle. Это логично, но снова — угадал.

3. Spec написан хорошо, но структура пакетов (store/, store/fs/, store/router/) следует из §1.4 spec-а — не из acceptance. Хорошо что я прочёл оба документа.

4. Тест на uuid монотонность использует time.Sleep(time.Millisecond) — это хрупко на загруженных машинах. uuid.NewV7() должен быть монотонен в рамках одного процесса даже без паузы (timestamp + sequence), но документация не гарантирует порядок без паузы. Оставил с паузой как разумный компромисс.
