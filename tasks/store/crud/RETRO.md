# Ретро: store/crud

_Дата: 2026-05-05_
_Участники: Танк, Ада Лавлейс, Гримм, Кроули, Азирафаль, Харли Куин_

## Что шло хорошо

- **Документация точная**: store/README.md, store/fs/README.md, store/fs/TECH.md, store/router/README.md — все 4 файла верифицированы против кода и прошли ревью
- **68/68 тестов зелёных**, race detector чист — полное покрытие happy path и adversarial
- **Ревью поймало 2 critical до прода**: path traversal (CRITICAL-1) и json omitempty (CRITICAL-2) — оба дефекта безопасности/корректности
- **Recall богатый**: 70 наблюдений от 6 участников — несмотря на то что notes не вели по ходу фичи
- **Pipeline v2 прошёл от начала до конца** как единица: research → spec → acceptance → tests → code → docs → retro

## Проблемы

### Требования

- **API-контракт до test-write** — источник: Азирафаль, Кроули, Гримм
  Два тест-агента угадывали сигнатуры конструкторов и интерфейсов независимо. Азирафаль предположил `captureLogger`; Кроули — `*slog.Logger`. Оба предположили что `*fs.Store` реализует три интерфейса одновременно — в Go невозможно. Обнаружила Ада в 04-code. Итог: 4+ лишних раунда review/fix.

- **Спека Go-specific без разделения контракт/реализация** — источник: Танк, Ада, Кроули
  Спека описывает `filepath.Join`, `named return`, конкретные сигнатуры — смешивает требования с реализацией. CR-15 предписал `filepath.Join` без проверки traversal — тот же баг всплыл как CRITICAL-1 в code-review.

- **Инварианты не документируются** — источник: Ада, Гримм
  Path traversal очевиден при написании `recordPath`, но не записан. Рецидив из store/connection: CR-7 → deadlock — инвариант тоже не был задокументирован.

### Процессные

- **Action items retro не конвертируются в задачи** — источник: Танк, Гримм, Кроули
  Из 8 пунктов "берём в работу" RETRO store/connection → 0 выполнено. Ретро создаёт список без owner, дедлайна, места хранения. Три из них, если бы были выполнены, сэкономили бы 2-3 раунда review в этой фиче.

- **Notes/complaints не пишутся по ходу** — источник: все участники
  Ни один агент не оставил notes/complaints в ходе фичи. Формат донесён только в 06-retro/01-recall. Детали первых прогонов размыты.

- **Порядок шагов нарушен: spec pending → code done** — источник: Танк
  spec-ft, spec-nft, spec-review остались в pending. Code, code-review помечены done. Оркестратор не блокирует переход при pending-вышестоящем. Симптом: корневой status.md появился снова вместо status-log.md процессов — агенты без инструментов пишут куда попало.

- **Нет fix-report / дыры в истории** — источник: Танк, Ада
  report-001 для 04-code/01-write не создан. Нет spec-fix-report ни в connection, ни в crud. Рецидив из RETRO connection.

- **Граница 03-tests / 04-code размылась** — источник: Кроули, Азирафаль
  Ада фиксила тесты в 04-code вместо clarification → 03-tests. Нет жёсткого правила о возврате.

### Инструментальные

- **Compile-fail и test-fail неразличимы** — источник: Кроули
  "setup failed" одинаково для Red phase и реальной ошибки компиляции.

- **Нет инструментов для чтения/записи статусов и notes** — источник: пользователь
  Статус фичи выясняется вручную: нужно открывать каждый status-log.md. Дозапись notes — аналогично. Без инструментов барьер к ведению notes слишком высок, и агенты пишут статусы в неправильные места.

### Командные

- **Несогласованность тест-агентов** — Кроули и Азирафаль работали в изоляции без сверки по API (входит в "API-контракт до test-write")
- **Граница тест/реализатор** — Ада вышла за рамки ответственности (входит в "граница 03-tests/04-code")

| Проблема | Решение | Приоритет |
